Sync your vault with git

Because the vault is plain markdown, git is the perfect companion: history, backup, and sync between machines, all free.

1. Put the vault under git

In a terminal, inside your vault folder:

cd /path/to/your/vault
git init
git add -A
git commit -m "Vault starts here"

2. Ignore what should not travel

Add a .gitignore in the vault root:

# OS noise
.DS_Store
Thumbs.db

# Large scratch files, if you keep any
*.tmp

Everything else — notes, images, PDFs you attached — is part of the vault and belongs in the repository. If some attachments are huge, consider git-lfs for them.

3. Push it somewhere

Create a private repository on your git host and add it as a remote:

git remote add origin git@github.com:you/notes.git
git push -u origin main
Private, not public. Notes feel innocent until you search them for names. Unless you are deliberately publishing, keep the repository private.

4. Edit from a second machine

  1. Clone the repository anywhere you like.
  2. Point KbWrite's vault path (Settings → Vault) at the clone.
  3. Before working: git pull. After working: git add -A && git commit -m "notes" && git push.

KbWrite watches the folder, so a pull while the app is open shows up immediately — no reload needed.

5. Automate the commit

A tiny shell alias or a cron job keeps the habit honest. For example, a launchd/cron entry that runs hourly: 

cd /path/to/your/vault && \
  git add -A && \
  git diff --cached --quiet || git commit -m "Auto-save $(date +%F %H:%M)" && \
  git pull --rebase && git push

Community plugins can do this from inside the app — see the plugin API: a command registered by a plugin can shell out to git on your behalf.

Conflicts

Markdown merges well. If two machines edit the same note, git stops and marks the conflict; open the file in KbWrite's Raw markdown view, resolve the <<</>>> markers, save, and commit. The block editor handles the rest.

Bonus: publish from the vault

Since notes are markdown, a static site generator can publish a selection of them. Keep the public notes in a subfolder, generate the site from it, and your knowledge base doubles as your website's source.
